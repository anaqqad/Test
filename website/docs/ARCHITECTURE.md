# Architecture

```
Internet ──► :80 / :443  Traefik v3 (existing, Compose project "n8n", /docker/n8n)  ── NOT modified
                │  routers by Host():
                ├── n8n.srv1998959.hstgr.cloud ──► n8n, images, bizdocsforge   (existing)
                └── theblackhistoryroom.com, www.… ──► bhr-wordpress           (new, via labels)

Compose project "bhr"  (/opt/blackhistoryroom)
  bhr-wordpress  wordpress:php8.4-apache   networks: n8n_default (for Traefik) + bhr_bhr_internal
  bhr-mariadb    mariadb:11.8              network: bhr_bhr_internal only (internal: no internet, no host port)
  bhr-redis      redis:7-alpine            network: bhr_bhr_internal only, 128 MB LRU, no persistence
  volumes: bhr_bhr_wp_files (/var/www/html), bhr_bhr_db_data (/var/lib/mysql)
```

## Isolation from n8n
- The n8n Compose file, `.env` and containers are untouched. Traefik discovers the new container through its
  labels; no Traefik restart is needed. Rollback: `cd /opt/blackhistoryroom && docker compose down` (volumes kept).
- MariaDB and Redis are only on `bhr_bhr_internal` (`internal: true`). Tested: from `n8n_default` neither
  `bhr-mariadb:3306` nor `bhr-redis:6379` is reachable, and neither port is published on the host.
- Only the WordPress web container joins `n8n_default`, so Traefik can reach it (and n8n can later call the REST API
  internally). Hostnames are the unique container names (`bhr-mariadb`, `bhr-redis`) so nothing can clash with
  other apps on that shared network.
- Memory limits: WordPress 768 MB, MariaDB 640 MB, Redis 192 MB, so a runaway site cannot starve n8n.

## Traefik labels (on bhr-wordpress)
- Router `bhr`: `Host(theblackhistoryroom.com) || Host(www.theblackhistoryroom.com)`, entrypoint `websecure`,
  Let's Encrypt via the existing `mytlschallenge` resolver, one certificate for both names.
- HTTP → HTTPS: the existing global redirect on the `web` entrypoint.
- `bhr-www`: `https://www.X` → `https://X` (301, path and query kept).
- `bhr-headers`: HSTS 1 year (no includeSubDomains/preload yet), nosniff, SAMEORIGIN, strict-origin-when-cross-origin
  referrer, restrictive Permissions-Policy, X-Powered-By removed.
- `bhr-compress`: gzip/Brotli for text responses.

## WordPress configuration (from `WORDPRESS_CONFIG_EXTRA` and `config/`)
- `WP_HOME`/`WP_SITEURL` fixed to https; `FORCE_SSL_ADMIN`; `DISALLOW_FILE_EDIT`; 10 revisions per post;
  automatic minor (security) core updates; Redis settings ready for the Redis Object Cache plugin (not installed yet).
- Unique auth keys/salts were generated by the image on first start and live in `wp-config.php` in the volume.
- Apache (`config/apache-bhr.conf`): real client IPs from Traefik (`mod_remoteip`), `xmlrpc.php`, `wp-config.php`,
  `readme.html`, `license.txt`, dot-files and logs return 403, long browser caching for images/fonts/CSS/JS.
- PHP (`config/php.ini`): PHP 8.4, `expose_php` off, 256 MB memory, 32 MB uploads, larger OPcache.
- MariaDB (`config/mariadb.cnf`): 256 MB buffer pool, 40 connections, utf8mb4.
